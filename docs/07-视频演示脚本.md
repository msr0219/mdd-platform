适用版本：2026-11-15。建议完整版25～30分钟，按章节分段录制。本文是录制方案，不代表其中页面流程已被实际验收；录制前的执行事项见[收尾任务清单](08-收尾任务清单.md)。

演示主题：JSON元模型驱动的低代码平台，以生产装配、质量处置和追溯作为复杂业务示例。

## 1. 录制前准备

- 启动后端，确认 `/health` 返回UP，页面能正常登录。使用IDEA运行时，JDK选择17，工作目录固定为项目的 `platform-server`。
- 演示选择固定地址，例如 `http://127.0.0.1:8080/`；录制时保持浏览器缩放一致，关闭无关标签页和通知。
- 关闭 `.env.mysql-test`、初始密码文件等标签页；密码框保持隐藏。使用演示账号和演示业务资料。
- 准备admin、业务A、业务B、全部范围只读账号、建模人员账号。使用不同浏览器配置文件登录，普通标签页会共享会话。
- B使用独立演示角色，勾选所需应用及编辑/业务操作，初始数据范围选“本人及所属记录”；后续改它的数据范围时不会影响其他业务账号。
- “全部范围只读”角色只勾所需应用的查看，数据范围选全部；全部范围不会自动赋予写入权限。
- 准备教室模型JSON及待追加的视图、菜单片段，放在便于复制的位置；视图追加至education.json，菜单统一追加至main.json。参考《04-建模与运行指南》第1节，先确认没有classroom同名编码。
- 预先完成一次彩排。正式录制使用新的编号前缀，例如 `VIDEO20261113A`，BOM编码、批次编号、工单编号及SN不能与彩排复用。
- 录制前保存数据库、meta、uploads的一致备份，按《06-完整功能验收清单》执行自动检查并保存日志。备份H2时先停机。

对“全部功能”的展示采用功能章节覆盖：页面上完整展示核心业务和代表性失败分支，并发、幂等、复杂回滚等用真实测试报告补充。若要求逐条展示所有失败用例，另录附录，不把尚未执行的操作当作通过。

## 3. 开场讲解词

> 大家好，本项目是一个基于Java 17、Spring Boot和Vue 3的模型驱动低代码平台。模型、视图、菜单和业务服务通过JSON描述，后端负责校验、数据库同步和业务执行，前端根据配置生成页面。接下来先新增一个教室模块，展示配置如何变成可操作的页面，再用生产装配场景演示权限、库存、BOM、返工和追溯。

目录画面停留约30～40秒，指出：

- platform-server：动态接口、事务编排、认证权限和附件服务。
- platform-web：动态页面和控件。
- meta/models、按应用分组的meta/views、集中菜单meta/menus/main.json、meta/services：四类配置。
- data/platform.mv.db：默认H2运行数据，账号和业务表在同一数据库。
- uploads：附件内容；JSON模型文件保存结构，业务记录保存在数据库。

说明已做MySQL兼容性测试，当前演示运行库以实际配置为准；`.env.mysql-test`是专项测试连接，不自动切换运行数据库。

## 4. 多用户和权限演示

### 4.1 账号管理

1. 管理员进入“用户与角色 → 用户账号 → 新增用户”。
2. 填写演示账号、姓名、初始密码、业务人员角色、启用状态，保存。
3. 新账号在独立浏览器配置中登录，展示首次强制改密，完成后进入工作台。
4. 指出当前新设密码最少6位，仍需字母与数字或符号组合；用户列表不返回明文密码。
5. 在一个额外专用账号上演示“重置密码”或“停用”：另一窗口旧会话失效。当前演示主账号A保留用于后续流程。
6. 展示管理员账号编辑与重置按钮禁用；角色编辑只保留应用勾选、平台管理权限及数据范围，没有补充权限。

讲解词：

> 账号由管理员分配，角色控制能执行的功能，数据范围控制能访问哪些记录。角色权限实时解析，账号停用、密码变更会撤销旧会话。

### 4.2 行级权限

1. A创建一条学生或设备记录，B按同编号搜索，列表应找不到；admin能看到。
2. 将A记录的详情地址放到B窗口，展示不可访问。
3. 管理员将只分配给B的演示角色改为“全部数据”，B刷新后可读取；撤销后再次不可读取。
4. 切换全部范围只读账号，显示它能读取全部可见工单，但不能新增、退库或管理账号。
5. 切换建模人员，说明可查看/重载配置，不能写业务数据。

讲解词：

> “能读全部”与“能修改”是独立权限。工单及其装配、核销和历史记录继承归属；批次、BOM和批次质量资料作为共享数据按功能权限管理。当前还没有部门隔离和多租户。

## 5. 建模与页面生成

1. IDEA展示新增classroom模型：教室编号roomNo必填且唯一，容量capacity为正整数。
2. 在meta/views/education.json中追加classroom_list、classroom_form视图配置，指出搜索项、列、按钮和表单字段。
3. 在meta/menus/main.json中追加教室菜单，引用classroom_list。若需要展示本人范围，在模型model中加rowScope.creator:true。
4. 使用有权限的账号点击“重载元模型”，展示新增菜单和可操作页面。
5. 新增一条教室记录，再编辑；输入负容量或重复编号，展示错误提示和数据未被错误保存。
6. 演示查询、排序、翻页、详情和当前页导出；可同时浏览现有学生、课程、设备页面，说明它们复用同一渲染机制。
7. 对新建教室配置做一次可恢复的JSON错误，重载失败后原页面继续可用；立即恢复正确配置再重载。
8. IDEA打开已注册的 `com.platform.custom.StudentCrudHandler`，指出 `modelCode()`、重写 `create` 和 `super.create`。使用新学号新增姓名两端有空白的学生，展示保存后的姓名已规范化。说明 Java 处理类编译启动时注册，JSON重载只处理元模型；其他模型和未重写动作继续复用通用实现。

讲解词：

> 这里通过配置定义字段、页面和入口，现有引擎就能提供常规数据操作。重载先做结构和语义校验，失败时保留旧快照。多步业务可用事务服务配置，专用计算与校验可在模型的Java处理类中实现，并调用通用保存。

不要在视频中把改字段类型或缩短已有列长度演示成“自动无损迁移”。自动DDL只负责建表、追加兼容字段和索引。

后端批量能力可在附录展示接口或自动测试证据：同模型 `batchCreate`、`batchDelete` 每批1～200条，删除逐条携带 `id/version`，任一记录失败整批回滚；默认批量动作复用Java单条规则。页面复选框只展示选中状态与数量，通用前端批量入口、批量更新和逐条部分成功不在交付范围。若展示JSONRPC请求数组，应说明各请求独立执行；重复请求防重仅适用于显式配置幂等的业务服务。

## 6. 一条可对账的生产主线

主流程使用A创建的单台工单，以下批次为新建且没有其他业务占用。B的跨用户质量场景另用独立数据，避免改变下表数量。

### 6.1 录前准备

| 对象 | 名称和数量 |
| --- | --- |
| 主板批次M | 零件名“演示主板”，GOOD，库存10 |
| 原内存批次R | 零件名“演示内存”，GOOD，库存10 |
| 补领内存批次R2 | 同名“演示内存”，GOOD，库存10 |
| 旧件接收批次BAD | 同名“演示内存”，BAD，库存0 |
| BOM | 产品“演示电脑”，版本V1；PRIMARY主板×1，DIMM_A内存×2 |
| 工单W | A按上述已发布BOM创建，计划1台 |

创建批次用管理员账号；日常领料、装配、退库等使用A。保持编号前缀一致，让视频中的记录容易辨认。

### 6.2 BOM发布、领料与装配

1. 创建BOM草稿，添加PRIMARY、DIMM_A，发布。可先试一次缺少PRIMARY的发布，展示被拒绝，补齐后成功。
2. 展示发布后的明细不可通过业务服务修改，A“按BOM创建工单”，计划1台。
3. A对工单领M 2件、R 3件；展示仓库库存M=8、R=7及ISSUE流水。
4. 工单推进到“装配中”，登记唯一SN，主要批次选择M。展示PRIMARY关系自动产生。
5. 此时执行齐套检查或提交检验，应因缺少内存失败，工单状态不变。
6. 在整机行“追加零件”，位置DIMM_A，批次R，数量2；再做齐套检查应通过。
7. 展示初装核销：主板1、内存2；仓库仍为8、7，装机不重复扣库。

讲解词：

> 工单绑定发布时选择的BOM版本。装配同时校验位置、零件种类、单机用量及本工单的领料余额；缺件不能提交检验。领料已经扣过仓库，装机只做核销，不重复扣仓库库存。

### 6.3 余料退库

1. 工单“领料余额”：M可退1、R可退1。
2. 分别退回1件并填写原因，展示仓库M=9、R=8，可退余额归零。
3. 展示RETURN_UNUSED流水和真实操作人。
4. 再尝试退1件，展示超额退库被拒绝，库存仍9、8。

核对表：

| 时点 | M仓库 | R仓库 | M首次核销 | R首次核销 | M可退 | R可退 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 初始 | 10 | 10 | 0 | 0 | 0 | 0 |
| 领料后 | 8 | 7 | 0 | 0 | 2 | 3 |
| 整机及内存装配后 | 8 | 7 | 1 | 2 | 1 | 1 |
| 余料退库后 | 9 | 8 | 1 | 2 | 0 | 0 |

讲解词：

> 可退数量等于同工单同批次的累计领料，减去首次装机核销和已退数量。已装机、已退回的材料不能重复退库，退回的材料也必须重新领料才能再装机。

## 7. 不良、返工与历史追溯

接着上一节的工单W，暂不完工：

1. 对原内存R登记不良2，填写原因、工位和代码。当前模型将可用库存R从8扣到6，生成隔离流水；整机HOLD、工单FROZEN。
2. 展示冻结状态不能正常推进；对已有装机关系的批次尝试“未装机库存返工”或直接报废，应被业务守卫拒绝。
3. 进入在用DIMM_A明细执行“返工更换”，选择对应不良单、补领R2和退旧BAD，填写原因。
4. 展示R2库存10→8、BAD库存0→2，旧关系active=false，新关系在用，新增更换历史及返工流水。
5. 展示原始初装核销仍为R 2件，返工走独立REWORK_ISSUE，不重复修改初装事实。
6. 提交复检，先登记FAIL，显示回到返工；完成相应处理后再次提交并登记PASS。
7. 确认不良单关闭，且没有其他未结异常时整机恢复RELEASED，工单回到原状态。
8. 在原批次查看历史装机，在新批次查看当前装机；在整机详情展示命名关联、去重结果和更换履历。

讲解词：

> 系统把质量异常与整机、工单关联起来，返工更换保留新旧关系和不可修改的历史。关闭一张不良单不等于无条件放行，仍会检查其他未结异常。

“另一张异常未关不能放行”和“两用户共享批次一起冻结”可用独立准备的分支完整录制，或放入附录并展示对应自动测试。共享批次的全局冻结/放行不因用户只能看本人工单而漏处理其他整机，调用结果也不返回他人工单明细。

## 8. 附件、其他质量分支与统计

### 8.1 附件

在刚才的不良单或检验记录详情“附件”页签中：

1. 上传准备好的演示图片或TXT，展示名称、大小、上传人和时间。
2. 下载并核对内容；移除后原下载入口不可用。
3. 上传非法扩展名文件，展示明确拒绝；单文件10 MiB及每记录20项上限，可用已验证的专项报告补充。
4. 只读账号不能上传；其他普通用户不能移除A上传的附件。共享质量记录的读取按功能权限管理。

讲解词：

> 附件属于业务记录，读取和写入都检查权限。数据库保存元信息及审计，文件保存在uploads；下载作为文件传输，不执行页面内预览。

### 8.2 来料检验与其他处置

使用独立批次：

- PENDING批次库存20，先试只检验5，展示待检批次需整批检验；再检验20、合格18、工时1，得到可用库存18和不良2的处置记录。
- 使用没有装机历史的独立批次，分别展示未装机返工、退货、报废和让步接收。可预先准备各分支的初始数据，但镜头中展示操作及结果，并说明准备状态。
- 打开“质量检验与指标”，按同一供应商/阶段核对检验数、合格数、工时；上述单条IQC记录合格率为90%。

讲解词：

> 统计口径来自已登记的检验记录，复检按检验次数累计。这些数字不等同于去重整机直通率；退货和报废处置也还没有对接外部物流或财务。

### 8.3 整机直通率与调用日志

1. 在“整机检验与直通率”给三台整机登记两台通过、一台未通过，再给未通过整机登记一次复检通过。
2. 展示四条检验记录、三台首次受检、两台首次通过及 66.67% 的直通率，说明复检不改变首次结果；演示柱状图、折线图及工单筛选。
3. 进入“平台管理 → 服务调用日志”，按 inspectMachine 筛选，展示操作人、参数摘要、幂等键、结果与耗时，再打开详情及调用链。
4. 使用自动化验收证据展示嵌套失败后的回滚日志；说明失败日志与业务事务独立保存。

## 9. 完工、重启和自动验证

1. 回到主工单W，使用更换后的当前零件再次齐套检查，提交检验、完成工单，展示状态历史。
2. 正常停止并重启一次服务，重新登录，按编号查找工单、库存、更换历史和附件；确认记录持续存在。
3. 展示录前真实执行的常规测试、前端构建、MySQL专项日志，指出日期、Failures、Errors和Skipped。以本次实际输出为准，不硬背历史测试数量。
4. 指出并发领料、相同requestId幂等、改参冲突、失败全回滚、跨账号权限和内部质量处理由相应用例验证。重新打开表单会生成新requestId，不用“关弹窗再提交”冒充幂等演示。
5. 如展示性能报告，明确其为独立H2内存库百万行、单调用者的服务层筛选分页数据，不能代表MySQL、行级权限或多人生产容量。

从项目根目录可执行的录前命令（CMD也可使用）：

```cmd
mvnw.cmd -f platform-server/pom.xml test -B -ntp
npm.cmd --prefix platform-web run build
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\test-mysql.ps1"
```

测试日志可以加速或剪掉等待过程，但保留命令和最终结果；若使用此前日志，注明运行日期。浏览器未操作的功能不能因接口测试通过而宣称已经完成人工验收。

## 10. 结束讲解词

> 本次演示展示了JSON建模与页面生成、模型Java定制、多用户功能权限和个人数据范围，以及BOM工单、装配核销、余料退库、质量返工、附件、图表和历史追溯。业务服务在同一事务中执行校验与变更，并通过显式幂等配置和版本控制处理重复请求及并发。交付范围为单层BOM；部门/多人共享授权、多租户、替代料和工程变更审批等生产化能力不属于本次交付范围。

## 11. 覆盖检查与录制节奏

录制完成后按《06-完整功能验收清单》核对覆盖。每个功能至少留下一个可辨认的“操作 → 结果”镜头；关键业务再留一个“错误输入 → 拒绝且状态/库存不变”镜头。

| 功能 | 主视频或附录应留的证据 |
| --- | --- |
| 账号 | 新增、首次改密、角色分配、专用账号重置/停用、退出 |
| 低代码 | 三类JSON、重载新增模块、错误重载保留旧页面、通用CRUD与校验、学生Java处理类 |
| 权限 | A/B可见差异、直接详情拒绝、范围授予/撤销、只读与建模角色 |
| BOM | 草稿、PRIMARY约束、发布冻结、绑定版本、缺件拦截与齐套 |
| 库存 | 领料前后数量、初装核销、余额、退库流水与超额拒绝 |
| 质量 | 隔离冻结、更换、失败/成功复检、其他异常未结限制及多用户影响 |
| 追溯 | 当前/历史关系、更换履历、去重关联和真实操作人 |
| 其他质量 | 来料整批检验、未装机返工、三类处置和统计口径 |
| 附件 | 上传/下载/移除、非法文件和越权拒绝、限额测试证据 |
| 稳定性 | 重启保留数据、事务/并发/显式幂等与后端批量回滚报告、实际MySQL执行记录 |

每次点击后停留1～2秒，让观众看到结果；表格可用同一编号筛选，避免在大量历史数据中找记录。先讲“准备做什么”，操作后讲“发生了什么变化”。失败分支出现时说明它是预期拦截，随后给出正确操作继续主线。

详细字段、所有失败用例和验收结果记录格式见《06-完整功能验收清单》；建模JSON完整模板见《04-建模与运行指南》。录制结果、交付物整理及未执行事项按[收尾任务清单](08-收尾任务清单.md)登记。
